# Markdown Note-Taking App

A simple RESTful API for creating, storing, rendering, and grammar-checking Markdown notes. Built with Node.js and Express.

## Features

- **Save notes** — upload a Markdown (`.md`) file along with a title
- **List notes** — retrieve all saved notes
- **Render notes** — get a note rendered as sanitized HTML
- **Update notes** — edit a note's title and/or replace its file
- **Delete notes** — remove a saved note
- **Grammar check** — check a note's writing quality via the LanguageTool API

## Tech Stack

- **Runtime:** Node.js
- **Framework:** Express 5
- **Templating:** EJS
- **File uploads:** Multer
- **Markdown rendering:** marked
- **HTML sanitization:** DOMPurify + jsdom
- **Grammar checking:** [LanguageTool API](https://languagetool.org/http-api/)
- **Storage:** Flat files (`storage/notes/`) + a JSON index (`data/notes.json`)

## Getting Started

### Prerequisites

- Node.js installed on your machine

### Installation

```bash
git clone https://github.com/Hicham-Hal/Markdown-Note-Taking-App.git
cd Markdown-Note-Taking-App
npm install
```

### Running the Server

```bash
npm start
```

The server will start on `http://localhost:3000`.

## API Endpoints

All endpoints are mounted under `/notes`.

| Method | Endpoint               | Description                              |
|--------|------------------------|------------------------------------------|
| GET    | `/notes`               | List all saved notes                     |
| POST   | `/notes`               | Save a new note (title + markdown file)  |
| GET    | `/notes/:id`           | Get a note rendered as HTML              |
| PUT    | `/notes/:id`           | Update a note's title and/or file        |
| DELETE | `/notes/:id`           | Delete a note                            |
| GET    | `/notes/grammar/:id`   | Check grammar of a note                  |

### List Notes

```bash
curl http://localhost:3000/notes
```

**Response**
```json
[
  { "id": "a1b2c3", "title": "My First Note", "fileName": "note.md" }
]
```

### Save a Note

Requires `multipart/form-data` with a `title` field and a `markdown` file field.

```bash
curl -X POST http://localhost:3000/notes \
  -F "title=My First Note" \
  -F "markdown=@/path/to/note.md"
```

**Response**
```json
{ "msg": "Note created" }
```

### Get a Rendered Note

```bash
curl http://localhost:3000/notes/a1b2c3
```

**Response**
```json
{
  "Note": { "id": "a1b2c3", "title": "My First Note", "fileName": "note.md" },
  "HtmlRaw": "<h1>My First Note</h1><p>...</p>"
}
```

### Update a Note

```bash
curl -X PUT http://localhost:3000/notes/a1b2c3 \
  -F "title=Updated Title" \
  -F "markdown=@/path/to/new-note.md"
```

The `markdown` field is optional — omit it to update only the title.

### Delete a Note

```bash
curl -X POST http://localhost:3000/notes/delete/a1b2c3
```

Returns `204 No Content` on success.

### Check Grammar

Checks the note's content for spelling and grammar issues using LanguageTool. Markdown syntax (code blocks, links, headings, emphasis) is stripped before the text is sent, so only prose is checked.

```bash
curl http://localhost:3000/notes/grammar/a1b2c3
```

**Response**
```json
{
  "issues": [
    {
      "message": "Possible spelling mistake found.",
      "issueType": "Possible Typo",
      "offset": 15,
      "length": 7,
      "suggestions": ["MongoDB"]
    }
  ]
}
```

## Error Handling

All endpoints return standard HTTP status codes:

| Status | Meaning                                  |
|--------|-------------------------------------------|
| 200    | Success                                   |
| 201    | Note created                              |
| 204    | Note deleted (no content)                 |
| 400    | Missing required field (title or file)    |
| 404    | Note not found                            |
| 500    | Server error                              |
| 502    | Grammar-check service unavailable         |

## Notes

- Uploaded HTML is sanitized with DOMPurify before being returned, to prevent XSS from note content.
- Note IDs are generated by Multer's file storage system and doubled as filenames on disk.
